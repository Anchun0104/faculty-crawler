# 高校教师信息采集工具：反爬恢复与人工验证设计

- 文档状态：待用户最终审阅
- 设计日期：2026-07-22
- 目标版本：第一阶段（纯脚本、本地桌面版，不接入 AI）
- 适用分支：`codex/anti-crawler`

## 1. 背景与目标

现有项目是一个基于 Python、Playwright 和 Tkinter 的高校教师信息采集工具。它可以从教师目录页面提取姓名、职称、个人主页和邮箱，支持部分普通分页、动态分页和延迟渲染，并将结果导出为 Excel。

现有实现已经能够诊断 HTTP 403、空响应、短 HTML、低覆盖率和 Playwright 加载异常，但尚未形成完整的反爬识别、自动恢复、人工验证、会话复用和问题回收体系。现有动态加载能力也没有系统覆盖 `Load more`、整页无限滚动、内部滚动容器和虚拟列表。

第一阶段的目标是：

1. 让完全没有编程或 AI 基础的同事通过本地桌面程序完成批量采集。
2. 自动处理可以安全恢复的常见访问障碍。
3. 将必须由人完成的验证放入非阻塞队列，避免中断整个批次。
4. 保存并复用合法获得的网站会话，默认 30 天后清理。
5. 覆盖普通分页、每页数量、`Load more`、无限滚动和内部滚动。
6. 对失败、低覆盖和结果不完整的任务生成可回收、可脱敏的问题报告。
7. 让问题报告可以半自动提交到普通飞书云文档文件夹，不依赖飞书管理员或开放平台应用。
8. 保持抓取核心的跨平台边界，为未来 macOS 安装包和 AI 能力预留清晰接口，但不在本阶段实现。

## 2. 已确认的产品决策

| 主题 | 决策 |
|---|---|
| 产品形态 | 第一阶段交付 Windows 本地安装程序 |
| 跨平台 | 抓取核心保持跨平台，未来单独制作 macOS 安装包 |
| 在线服务 | 第一阶段不建设纯在线采集服务 |
| AI | 第一阶段完全不接入 AI、AI 账号或 API Key |
| 人工验证 | 接受人工验证，但不自动破解验证码 |
| 批处理行为 | 验证任务进入非阻塞队列，其他任务继续 |
| 验证处理时机 | 用户在批次后主动点击“处理人工验证” |
| 会话保留 | 按网站保存 30 天，支持按网站清除和全部清除 |
| 动态内容 | 增加 `Load more`、整页滚动、内部滚动和虚拟列表支持 |
| 问题回收 | 所有失败和不完整结果保存脱敏诊断，可导出 ZIP |
| 飞书提交 | 打开共享飞书文件夹与本地 ZIP，用户完成拖放并标记已提交 |
| 飞书权限 | 不要求管理员协助，不创建飞书自建应用，不内置飞书密钥 |

## 3. 范围边界

### 3.1 本阶段包含

- 反爬和访问异常分类。
- 保守的限速、退避和有限重试。
- JavaScript 延迟页面等待。
- Cookie 弹窗处理。
- 普通分页、每页数量、`Load more`、无限滚动、内部滚动和虚拟列表。
- 非阻塞人工验证队列。
- 合法会话的本地保存、复用、过期和清除。
- 中断后的任务恢复。
- 低覆盖和结果完整性检查。
- 脱敏日志、结构化诊断、问题报告 ZIP 和半自动飞书提交。
- 面向零基础用户的桌面界面改版。
- Windows 安装包。

### 3.2 本阶段不包含

- AI 页面理解、AI 自主浏览或 AI 生成解析规则。
- 自动破解图片验证码、滑块、Turnstile 或其他挑战。
- 第三方验证码代答服务。
- 代理池、IP 轮换或浏览器指纹伪装。
- 绕过登录权限、付费墙或网站明确设置的访问控制。
- 飞书 API 自动上传、飞书机器人或在线诊断后台。
- 云端集中爬虫服务。
- macOS 安装包；仅保持代码边界可移植。

用户只能在自己有合法访问权限的情况下完成人工登录或验证。程序不保存用户输入的密码，不把验证页面中的敏感内容写入报告，也不尝试突破网站明确拒绝的访问范围。

## 4. 用户与核心场景

主要用户是不了解 Python、Playwright、HTTP、Cookie 和 AI 的业务同事。界面的单一核心任务是：

> 粘贴教师目录网址，开始采集，并清楚知道哪些完成、哪些需要人工处理、哪些需要把问题报告交回维护者。

核心流程：

```text
粘贴网址
  ↓
自动检查网址并开始批量采集
  ↓
正常任务继续完成 ─────────────→ Excel 结果
  ↓
需要验证的任务进入非阻塞队列
  ↓
批次结束后显示完成、待验证和未完成数量
  ↓
用户主动处理人工验证队列
  ↓
验证成功后复用会话并继续采集
  ↓
失败或不完整结果生成脱敏问题报告
  ↓
程序打开飞书文件夹和本地报告，用户拖放提交
```

## 5. 视觉与界面设计

### 5.1 视觉方向

视觉主题为“研究档案工作台”：可靠、清晰、接近学术数据整理环境，但不采用传统灰色管理后台模板。

颜色令牌：

| 名称 | 色值 | 用途 |
|---|---|---|
| 档案蓝 | `#17324D` | 导航、主文字 |
| 数据青 | `#177E89` | 主按钮、运行状态 |
| 清纸白 | `#F7F9FC` | 主背景 |
| 线框灰 | `#D7E0E8` | 分隔、边界 |
| 验证琥珀 | `#D88917` | 等待人工验证 |
| 异常红 | `#B84A4A` | 真正失败 |

字体使用系统字体，避免额外安装：中文使用 Microsoft YaHei UI，数字、网址和技术信息使用 Segoe UI，并提供系统回退字体。

特色元素是“任务状态轨道”：每个网址作为一份流转中的档案，显示等待、访问、展开、提取、验证、完成或未完成。该元素编码真实进度，不作为无意义装饰。

### 5.2 导航结构

```text
┌──────────────────────────────────────────────────────────┐
│ 高校教师信息采集工作台                      运行状态 ●   │
├────────────┬─────────────────────────────────────────────┤
│ 开始采集   │                                             │
│ 采集任务   │                当前页面                     │
│ 人工验证 3 │                                             │
│ 会话管理   │                                             │
│ 运行记录   │                                             │
│ 设置       │                                             │
└────────────┴─────────────────────────────────────────────┘
```

导航数字只表示真实待办数量。人工验证使用琥珀色，不用红色制造错误感。

### 5.3 开始采集

- 默认页面只要求每行粘贴一个网址。
- 粘贴后自动检查格式、重复项和任务数量。
- 默认自动生成安全的 Excel 文件名。
- 文件重命名放入任务详情，不阻塞主流程。
- 技术性的超时毫秒数移到高级设置。
- 主操作始终命名为“开始采集”。
- 无效网址在输入框下指出具体行，不使用长篇弹窗。

### 5.4 任务状态文案

任务使用下列有限状态：

- 等待采集
- 正在访问
- 正在展开内容
- 正在提取
- 等待重试
- 等待人工验证
- 验证后待继续
- 已完成
- 已完成，建议检查
- 未能完成
- 已取消

批次结束必须显示明确摘要，例如：

> 本次共处理 12 个网站：8 个已完成，3 个等待人工验证，1 个未能完成。

## 6. 页面识别与处理决策

页面访问后先分类，再决定动作。HTTP 状态码不能单独决定页面类型。

| 分类 | 典型依据 | 默认动作 |
|---|---|---|
| 正常目录 | 存在可信教师候选 | 继续采集 |
| 延迟加载 | 初始页面壳，内容随后出现 | 自动等待 |
| 动态内容 | 分页、按钮或滚动继续增加候选 | 自动展开 |
| 访问过快 | 429、频率限制文案 | 遵守等待时间后重试 |
| 临时网络故障 | 超时、连接中断、部分 5xx | 有限重试 |
| Cookie 遮挡 | 同意窗口覆盖目录 | 关闭或接受必要选项 |
| 人工验证 | 验证码、滑块、安全检查 | 加入人工队列 |
| 登录限制 | 必须登录且用户拥有合法权限 | 加入人工队列并提示 |
| 权限拒绝 | 403、Access denied | 综合特征后重试、验证或停止 |
| 解析不适配 | 页面正常但没有有效记录 | 保存诊断并停止 |
| 结果不完整 | 候选数与成功数明显不一致 | 导出部分结果并警告 |

识别结果使用结构化对象，至少包含：分类、置信依据、建议动作和可分享诊断字段。识别模块不直接操作 UI；UI 不自行分析反爬页面。

## 7. 限速、重试与访问策略

### 7.1 自动重试

- 网络超时最多重试 3 次，并逐次增加等待。
- 429 优先遵守 `Retry-After`。
- 部分 5xx 延迟后有限重试。
- JavaScript 页面壳继续观察内容和候选变化。
- 重试期间保存每次尝试结果。

### 7.2 不自动重复尝试

- 明确验证码或滑块。
- 明确登录要求。
- 多次出现且内容不变的 403。
- 网站明确拒绝访问。
- 已达到站点或单任务安全上限。

### 7.3 站点级节奏

- 同一网站同时只运行一个任务。
- 页面操作之间采用保守间隔。
- 同域名复用合法会话。
- 当前批次缓存已经成功读取的页面，避免重复访问。
- 某域名出现限流后，暂缓同域名的后续任务。
- 不使用代理轮换或指纹伪装。

## 8. 动态内容加载

### 8.1 处理顺序

```text
初始页面
  ↓
普通下一页链接
  ↓
更大的“每页显示数量”
  ↓
明确的 Load more / 显示更多
  ↓
整页无限滚动
  ↓
页面内部滚动区域
  ↓
连续无新增后停止
```

系统不能因为普通分页存在就跳过动态加载检查，也不能同时触发多个分页机制。每种机制执行后重新评估当前页面和剩余控件。

### 8.2 `Load more`

候选控件必须同时满足：

- 文本、`aria-label`、标题或可访问名称符合加载更多语义。
- 位于可信人员目录附近。
- 不是新闻、课程、导航、隐私或 Cookie 区域的“更多”。
- 控件未禁用。

每次点击前保存当前个人主页链接和候选记录集合；点击后等待加载动画结束、DOM 变化或候选增加。连续两轮点击无新增则停止。多语言词表按真实失败样本增量维护。

### 8.3 无限滚动与内部滚动

- 整页高度持续增加时滚动窗口。
- 页面高度不变但列表容器可滚动时滚动该容器。
- 虚拟列表每轮立即解析并合并，防止旧节点离开 DOM 后丢失。
- 每轮滚动使用可视区域大小，不瞬间跳到极限位置。

停止条件包括：

- 连续 3 轮没有新候选。
- 页面高度、容器高度和滚动位置不再变化。
- 出现明确的“已显示全部”。
- 达到最大轮数或最长运行时间。
- 出现验证、限流或异常页面。

### 8.4 完整性检查

动态加载完成后检查：

- 页面声明的总人数与采集数是否一致。
- 是否仍存在可用后续页或加载按钮。
- 滚动区域是否真正到底。
- 候选链接数与成功记录数是否差距异常。
- 是否有大量人员缺少职称。

不确定完整时输出 Excel，但状态标记为“已完成，建议检查”。

## 9. 人工验证队列

### 9.1 非阻塞原则

发现人工验证后：

1. 保存任务、原始网址、当前网址、识别依据和诊断信息。
2. 将任务标记为“等待人工验证”。
3. 关闭或释放当前抓取页面。
4. 继续处理其他网站。
5. 批次结束后由用户主动进入验证队列。

### 9.2 用户操作

用户点击“开始验证”后，程序打开可见浏览器并恢复目标页面。用户完成网站要求的验证码、滑块或合法登录。程序自动检查教师目录是否出现；无法自动确认时，用户可点击“我已完成验证”触发检查。

验证成功后：

- 保存该域名的会话。
- 将任务设为“验证后待继续”。
- 继续动态加载、解析和导出。

验证仍失败时：

- 保留任务和诊断。
- 允许“暂不处理”。
- 不无限重新打开验证页面。
- 多次失败后标记为“未能完成”，但仍可稍后重试。

## 10. 会话管理

- 会话按站点隔离，不能跨域读取。
- 默认保存 30 天。
- 程序启动和批次结束时清除过期会话。
- 支持按网站清除和一键清除全部。
- 清除前二次确认。
- 界面只显示网站、保存时间、最近使用时间和清理时间，不显示 Cookie 值。
- 清除后同步释放内存与磁盘状态。
- 会话不进入 Excel、日志、安装包或问题报告。
- Windows 版本使用操作系统保护能力保存敏感状态；存储接口与操作系统解耦，便于未来接入 macOS 钥匙串。

## 11. 任务持久化与中断恢复

每次任务状态变化立即持久化。程序异常关闭、浏览器退出、电脑休眠或断网后，已经完成的任务、待验证任务和诊断不能丢失。

重新启动时，将上次处于运行态的任务转换为“可恢复的中断任务”，并提示：

> 上次运行意外中断。3 个任务可以继续。

用户可以继续上次任务，或结束批次但保留记录。一个任务的异常不能终止整个批次。

## 12. 本地文件与保留策略

Excel 继续保存到用户选择的目录。程序内部数据放在操作系统规定的用户应用数据目录，而不是安装目录：

```text
应用数据/
├── tasks/          任务与人工验证队列
├── sessions/       站点会话
├── runs/           结构化运行记录
├── logs/           脱敏日志
├── reports/        问题报告 ZIP
├── screenshots/    允许保存的诊断截图
└── settings/       用户设置
```

默认保留规则：

| 数据 | 保留时间 |
|---|---|
| 未提交的问题报告 | 一直保留，直到用户处理 |
| 已标记提交的问题报告 | 30 天 |
| 普通成功任务详细日志 | 30 天 |
| 失败或建议检查的运行记录 | 90 天 |
| 网站会话 | 30 天 |
| 临时缓存 | 批次完成后清理 |

设置页显示各类数据占用空间。清理程序内部数据不能删除 Excel 结果。

## 13. 诊断与问题报告

### 13.1 必须记录

- 批次 ID、任务 ID、应用版本和时间。
- 原始网址、最终跳转网址和站点域名。
- 失败阶段与失败分类。
- HTTP 状态码和安全响应头摘要；不记录认证值。
- 每次重试、等待和恢复动作的结果。
- 页面标题、HTML 长度和识别出的页面类型。
- 候选数、成功记录数、缺失职称数和低覆盖指标。
- 普通分页页数、每页数量调整、`Load more` 点击次数。
- 每轮滚动新增数量和动态加载停止原因。
- 操作系统、Python、Playwright 和浏览器版本。
- 脱敏后的异常信息与调用栈。

### 13.2 禁止记录

- Cookie、Authorization、Token、API Key 和密码。
- 用户在验证页面输入的内容。
- 完整私人页面正文。
- 飞书账号或凭证。
- 未经允许的登录后页面截图。

### 13.3 ZIP 白名单

问题报告只允许包含：

```text
问题报告-<批次>.zip
├── summary.txt
├── diagnostics.json
├── failed-tasks.csv
├── application.log
└── screenshots/        可选
```

ZIP 采用白名单生成，不能直接压缩整个日志或应用数据目录。截图默认只用于公开的挑战页、空白页或错误页；导出前列出截图并允许用户取消。登录后页面或无法确认隐私边界的页面不自动加入截图。

### 13.4 飞书半自动提交

由于不使用管理员权限或飞书开放平台应用，程序不自动调用飞书 API。

用户配置一个普通飞书云文档共享文件夹链接后，点击“提交问题报告”执行：

1. 生成并再次检查脱敏 ZIP。
2. 打开本地目录并选中 ZIP。
3. 打开配置好的飞书文件夹链接。
4. 提示用户把 ZIP 拖入飞书文件夹。
5. 用户点击“标记为已提交”。

未标记提交的报告持续显示在“待提交问题”列表中。无法打开飞书或断网不影响本地报告。

## 14. 内部模块边界

```text
桌面界面
  ├── 批次与任务管理
  ├── 页面访问控制
  ├── 页面状态识别
  ├── 动态内容加载
  ├── 现有教师解析器
  ├── 人工验证队列
  ├── 会话管理
  └── 诊断与问题报告
```

职责：

- 批次与任务管理：状态机、持久化、中断恢复和同域名调度。
- 页面访问控制：浏览器生命周期、限速、等待和重试。
- 页面状态识别：只分类并提供依据，不执行 UI 操作。
- 动态内容加载：只负责发现并展开更多结果，输出页面快照或增量记录。
- 教师解析器：继续负责字段提取、去重和完整性指标。
- 人工验证队列：管理待办和可见浏览器接管。
- 会话管理：站点隔离、系统保护、过期和清理。
- 诊断与报告：结构化事件、脱敏、保留和 ZIP 白名单。
- 桌面界面：呈现状态与用户动作，不包含反爬判断规则。

## 15. 异常处理原则

需要覆盖：

- 浏览器意外退出。
- 运行中关闭应用。
- 电脑休眠、断网或网络切换。
- 输出 Excel 被占用。
- 磁盘空间不足。
- 日志无法继续写入。
- 会话文件损坏。
- 问题报告压缩失败。
- 飞书链接无法打开。

统一原则：

1. 先保存可用诊断，再改变任务状态。
2. 单任务异常不终止整个批次。
3. 不删除已经生成的部分结果。
4. 报告提交失败不影响本地保存。
5. 对用户说明发生了什么和下一步能做什么。

## 16. 测试设计

### 16.1 单元与集成测试

- 403、429、5xx、空响应、短响应和超时分类。
- 验证码、登录页和挑战页特征识别。
- `Retry-After`、退避和最大重试次数。
- 同域名串行和限流后的延后调度。
- 普通分页及循环分页保护。
- 每页数量切换。
- `Load more` 成功、无新增、禁用和误匹配保护。
- 整页滚动、内部滚动、停止条件和虚拟列表合并。
- 人工验证任务不阻塞后续任务。
- 验证成功后的任务恢复。
- 会话按域名隔离、30 天过期、单站点清除和全部清除。
- 中断后恢复。
- 低覆盖和不完整结果警告。
- Cookie、Token、Authorization、密码样本和敏感页面内容脱敏。
- ZIP 白名单和会话目录排除。
- 现有解析器与导出测试保持通过。

网络、时间、浏览器和页面变化必须可以用测试替身控制，避免单元测试依赖真实网站或真实等待。

### 16.2 界面验收

- 用户无需修改技术参数即可开始采集。
- 无效网址能定位到具体输入行。
- 批次状态、记录数和验证待办清楚可见。
- 验证任务可以逐个处理、暂不处理和重试。
- 会话可以按网站或全部清除。
- 运行中断后能够恢复。
- 问题报告能够定位、打开飞书链接并标记已提交。
- 错误文案不要求用户理解 HTTP 或浏览器术语。
- 常用键盘操作、焦点状态和窗口缩放可用。

### 16.3 真实网站验收

使用少量代表性页面逐类验证：

- 静态教师目录。
- JavaScript 延迟渲染目录。
- 普通分页。
- `Load more`。
- 无限滚动和内部滚动。
- Cookie 弹窗。
- 需要人工验证的实际或受控页面。
- 受控的 403、429 和超时页面。
- 页面正常但解析器暂不支持的样本。

真实网站测试采用低频、串行访问，并保存诊断，不以高并发压测外部网站。

## 17. 第一阶段验收标准

以下条件全部满足才视为完成：

1. 零基础用户可以从安装到 Excel 导出独立完成操作。
2. 常见临时网络和访问错误能够有限自动恢复。
3. 动态目录不会因未点击或未滚动而只采集首屏。
4. 人工验证不会阻塞整个批次。
5. 验证后会话能够复用，并在 30 天后自动清理。
6. 用户能按网站或全部清除会话。
7. 程序异常退出后，任务和诊断不会无声丢失。
8. 失败、低覆盖和不完整结果都能生成可回收的脱敏报告。
9. 问题报告不包含会话、密码、Token 或飞书凭证。
10. 飞书提交流程不依赖管理员或开放平台权限。
11. 现有解析和导出能力不回退，自动化测试全部通过。
12. 第一阶段不要求任何 AI 能力、账号或密钥。

## 18. 未来阶段接口（不在本次实现）

未来 AI 层只能通过既有接口接收：页面状态、脱敏 DOM 摘要、动态控件候选、解析指标和允许执行的动作。AI 不能直接读取会话密钥，不能绕过验证码或访问控制，也不能跳过结果校验。

未来在线诊断或飞书自动上传需要独立安全设计，包括身份、权限、传输加密、密钥托管、数据保留和用户授权，不能通过把管理员密钥写入安装包实现。

## 19. 设计自审结论

- 占位项：无未决占位项或未决定的第一阶段功能。
- 一致性：本地安装、无 AI、人工验证、30 天会话和半自动飞书提交前后一致。
- 范围：第一阶段聚焦访问恢复、动态加载、人工验证、诊断和桌面可用性；在线服务与 AI 已明确排除。
- 隐私：会话、密码、Token 和私人页面不进入问题报告；ZIP 使用白名单。
- 可验证性：每项核心能力均有自动化或界面验收标准。
- 已知取舍：不使用飞书 API 意味着报告提交仍需要用户拖放文件，但避免管理员权限和客户端密钥风险。
