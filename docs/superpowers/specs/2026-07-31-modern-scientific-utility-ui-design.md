# Faculty Crawler — Modern Scientific Utility UI Design

## 1. 目标与边界

本设计将 Faculty Crawler 的 Windows 桌面端重塑为“Modern Scientific Utility”：现代、精确、平静、略带技术感，适合非技术操作员长时间办公。设计保持现有产品能力边界，不改变采集、验证、会话、运行历史、输出或诊断的业务语义。

本阶段只交付设计规范、可浏览 mockup 与渲染截图，不改动当前 Tkinter 应用，也不引入 QFluentWidgets。未来实现应优先采用原生 PySide6 与项目自有 QSS；在引入任何第三方组件前必须单独核对许可证。

主设计画布为 1440 × 900，最小可用窗口为 1180 × 720。窗口缩小时依次压缩内容留白、收起右侧检查器、将左侧导航折叠为图标栏，不缩小基础字号。

## 3. 信息架构

应用一级导航分为三组：

- 工作：概览、任务、人工验证
- 记录：运行记录、站点会话
- 系统：设置

直接 URL 与批量 XLSX 通过统一的“新建采集”对话框进入，不增加一级页面。设置页内部包含常规、采集、翻译与 AI、存储与诊断、关于五个分组。

后台状态常驻左下角，以状态点、文本和任务数量显示空闲、运行中或等待人工操作。页面级通知使用 InfoBar；无需决策的短暂反馈使用 Toast；破坏性操作使用确认对话框。

## 4. 页面设计

### 4.1 概览

顶部提供唯一主操作“新建采集”。首屏左侧是直接 URL/批量 XLSX 的统一启动入口，右侧是当前运行。下方只显示需要关注的数量和最近任务，不提供装饰性分析图。

### 4.2 任务

工具栏包含搜索、状态分段筛选、筛选器和更多菜单。任务表默认 40 px 行高；选中行使用浅蓝色背景。右侧 360 px 检查器显示来源、阶段、进度、记录数、输出位置与上下文操作。窗口不足时检查器变为覆盖式抽屉。

### 4.3 人工验证

顶部 InfoBar 明确合规边界。左侧为验证队列，右侧为所选站点、可见浏览器状态、三步操作说明和开始/暂缓/完成按钮。界面不得暗示 CAPTCHA 自动破解、权限绕过或跨主机会话复用。

### 4.4 运行记录

左侧显示运行批次，右侧显示接受、复核、排除数量和阶段时间线。错误只展示脱敏摘要、失败阶段与建议行动。可打开输出目录并导出运行报告。

### 4.5 站点会话

使用单一安静表格展示精确主机、保存时间、最近使用、计划清理和行级清除操作。临近到期使用警告状态。批量清理在顶部作为低强调度破坏性操作。

### 4.6 设置

设置内部使用 220 px 分类导航。页面顶部搜索可定位设置项。每个分组由标题和设置行组成；行内控件右对齐。高级设置默认折叠，但搜索命中时自动展开并聚焦。

### 4.7 存储与诊断

容量展示只使用单条分段使用条，显示页面快照、翻译缓存、日志和其他数据。清理操作逐类提供，并明确可否重新生成。清除内部数据必须确认。诊断说明必须列出被包含和明确排除的数据类型。

### 4.8 新建采集对话框

对话框先选择“直接 URL”或“批量 XLSX”，随后只显示对应字段。开始前显示访问合规提示、输出位置和关键运行选项。主要按钮为“开始采集”，取消为次要按钮。

### 5.5 动效

- `motion.fast=120 ms`
- `motion.standard=160 ms`
- `motion.slow=180 ms`

- 仅用于导航折叠、检查器/抽屉进入、菜单和状态过渡
- 遵循系统“减少动态效果”偏好；禁止循环动画和装饰性位移

## 6. 图标规则

未来实现采用项目自有 SVG 图标资源或许可证兼容的开源线性图标。统一 1.5–2 px 描边、圆角端点、16 px 默认尺寸。一级导航使用 18 px；按钮使用 16 px；空状态使用 32 px。图标与文字间距 8 px。

图标不得单独承担不熟悉的操作含义。图标按钮必须有可访问名称和 Tooltip。危险操作不使用夸张的填充红色图标；仅在确认对话框主操作中使用危险色。

## 7. 组件与状态规则

### 按钮

- 每个视觉区域最多一个主按钮。
- 次要按钮为白底细边框；低强调操作为幽灵按钮。
- 破坏性按钮默认使用红色文字和边框；确认对话框内可用红色填充。
- 禁用态保留可辨识文字，透明度不低于 45%。

### 输入

- 默认高度 34 px，边框 1 px，圆角 8 px。
- 聚焦时显示 2 px 外焦点环，不以边框颜色变化作为唯一提示。
- 错误信息紧邻字段下方，并说明修正方式。

### 表格

- 表头 36 px、正文行 40 px；不使用垂直网格线。
- 选中行使用 `primary.soft`，文本保持深色。
- 数字右对齐并使用 tabular nums。
- 批量操作只在存在选择时出现。
- 横向空间不足时优先隐藏低优先级列，并在检查器中保留完整信息。

### 状态

标准任务状态：排队中、运行中、完成、等待人工验证、建议复核、失败、已停止。每种状态均包含图标、文字和稳定色彩映射。运行中可使用静态进度条；不使用无限旋转动画作为唯一状态。

### 通知

- InfoBar：需要阅读但不中断流程的页面级状态。
- Toast：保存、复制、导出开始等短暂反馈，4–6 秒自动消失。
- Dialog：不可逆操作、访问合规确认、关键错误决策。
- 错误应给出“发生了什么、影响是什么、下一步做什么”。

### 空状态

只包含 32 px 线性图标、明确标题、一句原因/说明和至多一个主操作。无大幅插画、装饰图表或营销语言。

## 8. 可访问性与键盘

- 正文对比度至少 4.5:1，大文本至少 3:1。
- Tab 顺序遵循左到右、上到下；列表与表格使用方向键移动。
- `Ctrl+F` 聚焦当前页面搜索；`Ctrl+,` 打开设置；`Ctrl+N` 打开新建采集。
- `Esc` 依次关闭菜单、抽屉、对话框，不直接停止任务。
- 所有交互提供至少 2 px 明显焦点环。
- 窗口缩放、125%/150% DPI 和中英文混排必须保持不截断。

## 9. 响应规则

- `>=1360 px`：220 px 导航 + 主内容 + 360 px 检查器。
- `1180–1359 px`：导航可保持 220 px；检查器可由用户关闭，表格隐藏低优先级列。
- `<1180 px`：非正式支持范围；导航自动折叠到 56 px，检查器以覆盖抽屉呈现。
- 高度不足时仅内容区滚动，标题栏、一级导航和页面工具栏保持固定。

## 10. 设计交付与验收

可浏览 mockup：`docs/design/faculty-crawler-ui-mockups.html`。

应渲染以下 8 个 1440 × 900 页面状态：

1. 概览
2. 任务 + 右侧检查器
3. 人工验证
4. 运行记录
5. 站点会话
6. 常规设置
7. 存储与诊断
8. 新建采集对话框

验收标准：视觉与本规范一致；中文文字无乱码；1440 × 900 无裁切；状态不只依靠颜色；主要操作层级明确；不出现本项目范围外的项目管理、团队共享或 CAPTCHA 绕过功能。
