# 版本演进与 2.1.0 发布文档设计

## 目标

建立一套可持续维护的版本说明，使用户在仓库首页即可了解每个版本新增了什么、解决了什么问题、适合怎样使用，以及需要回退时应如何操作。文档必须与 Git 标签、GitHub Release 和实际安装包保持一致。

本次同时为正在准备的 `2.1.0` 整理正式发布说明，但在标签、安装包和 GitHub Release 尚未创建前，所有公开文档必须明确标注为“待发布”。

| 版本 | Git 标签 | 发布定位 | 安装包状态 |
| --- | --- | --- | --- |
| `1.0.0` | `v1.0.0`，提交 `cf93c7e` | 可重建的历史源码基线 | 没有可验证的历史安装包 |
| `2.0.0` | `v2.0.0`，提交 `5e04a28` | 当前已发布的稳定安装包版本 | GitHub Release 已保留安装包、源码 ZIP 和 SHA-256 文件 |

## 文档结构

### `README.md`：面向所有用户的入口

在靠前位置增加“版本演进”表，每个版本使用一行说明：

- 版本定位与主要用户；
- 关键新增能力；
- 当前可用的下载/源码入口；
- 与上一版本相比的主要变化。

README 同时保留简短的“选择使用方式”说明：普通用户使用 Windows 安装包；Codex、脚本和兼容模型用户阅读 `README_WORKFLOW_AI.md`。当前稳定下载链接固定指向 `v2.0.0`，直到 `v2.1.0` Release 实际发布后才切换。

README 还将加入“发布与回退”小节，说明：标签是版本锚点；已发布问题优先通过新提交和 `git revert` 修复；旧版本可从对应标签检出；`1.0.0` 可使用当时的构建脚本重新生成安装包。

### `CHANGELOG.md`：版本功能的唯一完整索引

新增中文变更日志，按版本倒序记录，采用固定栏目：

- `新增`：可由用户使用的新能力；
- `改进`：已有能力的可靠性、速度或使用体验变化；
- `兼容与安全边界`：输入、AI、证据和数据处理约束；
- `发布状态`：已发布或待发布。

`2.1.0` 只记录当前分支确实具备的能力：统一直接 URL/XLSX 入口、官方证据与快照、PDF/二级来源、轻量确定性邮箱解码、目录快速路径、按来源类型的超时重试、有限 review/unresolved 生命周期、`run_report.json` 诊断、可选兼容 AI 与密钥边界。不得把未实现的自动目录发现、邮箱猜测或安装包体积优化写成已完成能力。

`2.0.0` 记录离线多语言职称分类和现有 Windows 安装包；`1.0.0` 记录为历史源码基线，避免虚构历史二进制资产。

### `RELEASE_NOTES_2.1.0.md`：单个版本的发布说明

重写为面向 2.1.0 发布的简明说明，并链接至 `CHANGELOG.md` 获取完整历史。内容包括：

- 从 2.0.0 升级后获得的工作流能力；
- 速度策略：完整目录信息可跳过个人页，个人页采用快速失败，目录页保持较稳健策略；
- review 的终态和人工重新打开条件；
- 输出文件及 `run_report.json` 的用途；
- 默认本地模式、AI 仅处理已抓取页面的限制；
- 发布时需要补入的最终标签、安装包文件名和 SHA-256。

在发布前，文档不得声称安装包已存在或测试/发布已完成。

### `README_WORKFLOW_AI.md`：脚本用户的专项说明

保留当前具体命令和安全边界，增加链接到 README 的版本演进和 CHANGELOG。更新导出说明，使其与当前实现一致：正式结果、`review_queue.xlsx` 和 `run_report.json`；不再声称默认导出证据 Excel 或旧 `audit.json`。

## 内容一致性规则

1. `VERSION`、Git 标签、GitHub Release 标题必须使用同一语义版本号。
2. 安装包下载链接只能指向包含该版本实际资产的 Release。
3. 发布前文档使用“待发布”；发布后才替换为安装包链接、文件大小和 SHA-256。
4. CHANGELOG 是版本功能的完整索引；README 只保留摘要，避免两处功能清单逐字复制后漂移。
5. 每次后续版本发布必须更新 CHANGELOG、README 摘要、对应 RELEASE_NOTES、标签和 Release；缺少任一项不得标为正式发布。

## 验收标准

- README 可清楚区分 1.0.0、2.0.0、2.1.0 的定位与状态。
- README 的 2.0.0 下载链接可访问规范化的 `v2.0.0` Release。
- CHANGELOG 内容只包含可由当前代码或已验证发布资产支持的表述。
- 2.1.0 的三份文档对输出、AI 边界、速度策略和 review 生命周期没有矛盾。
- 发布 2.1.0 前，文档不提供不存在的下载链接；发布后，Release 资产与 SHA-256 被回填并校验。
