# Faculty Crawler UI 完整视觉重做设计

日期：2026-08-03  
状态：设计已获用户确认，等待文档审阅  
范围：PySide6 桌面端 UI 与视觉验收支持，不包含业务逻辑重构

## 1. 目标

将 Faculty Crawler 当前的 PySide6 桌面端重做为批准的 Modern Scientific Utility 风格，并满足以下用户可见要求：

- 应用名称、一级导航、页面标题、按钮、状态、空状态、InfoBar、Toast、确认弹窗和设置页全部使用简体中文。
- API、URL、Token、Excel/XLSX、DeepSeek、Windows DPAPI、robots 等必要技术名称可以保留英文。
- 页面结构、密度、层级和控件外观对齐 `docs/superpowers/specs/2026-07-31-modern-scientific-utility-ui-design.md` 与 `docs/design/faculty-crawler-ui-mockups.html`。
- 以真实运行的 PySide6 窗口截图作为验收依据，不以源代码或 QSS 静态检查替代。
- 在视觉验收完成前不推进 2.2.0 发布。

## 2. 范围与不变量

### 2.1 包含范围

本次重做可以修改：

- `desktop_ui` 中的窗口外壳、页面布局、共享控件、图标呈现、QSS、文案和可访问名称。
- 新建采集对话框的视觉布局、字段呈现、校验摘要和状态反馈呈现。
- 为截图验收提供的独立 worktree 内存演示数据 fixture 与启动入口。
- UI 相关的截图验收、可访问性和中文文案测试。

### 2.2 不包含范围

本次重做不得修改：

- 抓取、解析、标题分类、邮箱解析、质量判定或导出业务逻辑。
- 任务状态机、数据库 schema、运行历史持久化、会话加密或保留策略。
- 可见浏览器的人工验证边界；不得自动破解 CAPTCHA、绕过访问控制或跨主机复用会话。
- AI 请求协议、API Key 存储、Token 计算和预算决策。
- 2.2.0 版本号、发布流程、打包配置或生产默认数据。

### 2.3 视觉验收 fixture

真实截图需要同时覆盖空数据和设计稿中的有数据状态。为此在独立 worktree 提供确定性、内存内的 UI fixture：

- 不读取或写入用户生产数据库，不调用网络、AI 或浏览器。
- 不改变默认生产启动路径；只有明确的验收 fixture 启动选项才启用。
- 提供四条任务：运行中、等待人工验证、已完成、排队中。
- 提供一条运行时间线、已接受/建议复核/已排除指标、三条站点会话（其中一条临近到期）和 20 条批量 URL 输入。
- 所有示例名称、域名、时间和数量固定，确保不同截图运行之间可比较。
- fixture 只为视觉和交互烟雾验收服务，不成为产品默认演示内容。

## 3. 信息架构与应用外壳

### 3.1 一级导航

导航分为三组，使用中文名称：

- 工作：概览、任务、人工验证
- 记录：运行历史、站点会话
- 系统：设置

应用可见名称统一为“教师目录采集器”。必要的技术字段可以在正文中保留 Faculty Crawler、API、URL、Token、Excel/XLSX、DeepSeek 等技术名，但不得用英文替代中文导航或操作文本。

### 3.2 外壳尺寸

设计基准为 1440×900，最小正式支持尺寸为 1180×720：

| 区域 | 尺寸或行为 |
| --- | --- |
| 左侧导航 | 展开 220px；窄窗口折叠为 56px 图标栏 |
| 标题栏 | 48px，保留最小化、最大化、关闭与可访问名称 |
| 页面标题/工具栏 | 64–76px，标题、说明和唯一主操作分层 |
| 右侧检查器 | 360px；横向空间不足时可关闭或变为覆盖式抽屉 |
| 内容区 | 仅内容滚动；标题栏、一级导航和页面工具栏保持稳定 |
| 字号 | 正文和交互文字不低于 12px；不因窗口缩小而压缩基础字号 |

窗口背景使用 `#F4F7FA`，导航背景使用 `#EDF2F7`，卡片和表格使用白色表面。常驻卡片不使用明显阴影；浮层、对话框和抽屉使用轻微阴影。

## 4. 视觉令牌与共享组件

### 4.1 令牌

- 主文字 `#18212F`，次文字 `#667085`，辅助文字 `#98A2B3`。
- 默认边框 `#DFE5EC`，细分隔线 `#EDF1F5`。
- 主色 `#1769AA`，悬停 `#125C97`，按下 `#0E4E82`，浅主色 `#E8F2FB`。
- 成功 `#17875B` / `#E8F6EF`，警告 `#B56A08` / `#FFF3DC`，危险 `#C53B3F` / `#FDECED`，信息 `#3976C6` / `#EEF7FE`。
- 控件高度：小 28px、中 34px、大 40px；控制圆角 8px、面板圆角 12px、对话框圆角 14px。
- 表头 36px，表格普通行 40px，舒适行 48px。

### 4.2 共享组件边界

共享组件必须承担单一视觉职责，并通过现有 facade/model 信号接收状态：

- `AppShell`：标题栏、一级导航、后台状态、页面容器。
- `PageHeader`：中文标题、说明、唯一主操作。
- `InfoBar`、`Toast`、确认对话框：分别承担页面级提示、短暂反馈和不可逆操作确认。
- `StatusBadge`：图标、中文状态文本和稳定色彩同时呈现。
- `MetricCard`、`EmptyState`、`DataTable`、`InspectorPanel`：统一数据展示和空状态层级。
- `SettingsGroup`、`SettingsRow`、`ChoiceCard`：统一设置和对话框结构。
- `ProgressBar`、`Timeline`、`MockBrowserCard`：统一运行进度、事件阶段和人工验证视觉。

所有交互控件必须有可访问名称、键盘焦点环和可辨识的禁用文本。图标不能单独承担陌生操作的含义。

## 5. 页面设计

### 5.1 概览

页面标题为“概览”，顶部唯一主操作为“新建采集”。首屏包含：

1. “采集教师目录”快速启动卡，说明直接 URL 与批量 XLSX 入口。
2. “当前运行”卡，显示任务名、阶段、进度、预计剩余时间和“查看任务”。
3. “需要关注”指标：等待人工验证、建议复核、近 7 天成功率。
4. “最近任务”表格，展示 fixture 的四种任务状态。

无任务时保留页面标题、指标卡和启动入口，空状态使用线性图标、中文标题、简短说明和至多一个主操作。

### 5.2 任务

页面标题为“任务”，说明为管理采集队列、状态与输出。工具栏提供搜索、状态分段筛选、筛选器和更多菜单。任务表使用紧凑 40px 行高，选中行使用浅蓝背景并保留深色文字。

右侧 360px 检查器展示来源、当前阶段、进度、已接受、建议复核、输出位置和上下文操作。检查器空间不足时只作为抽屉出现，不挤压基础表格字号。

### 5.3 人工验证

页面标题、合规 InfoBar、队列、站点信息、浏览器状态、三步说明和操作按钮全部中文化。右侧必须明确：

1. 打开可见浏览器。
2. 用户自行完成网站要求的登录或验证。
3. 返回应用标记完成或暂缓。

视觉层面使用 `MockBrowserCard` 表示可见浏览器状态；真实浏览器启动仍由既有 workflow 行为控制，fixture 截图不触发浏览器或网络。

### 5.4 运行历史

左侧为运行批次列表，右侧显示运行名称、运行 ID、来源、状态、已接受/建议复核/已排除指标、阶段时间线和脱敏错误摘要。页面操作包括“打开输出目录”“查看任务”和导出报告；错误内容必须说明发生了什么、影响和下一步动作。

### 5.5 站点会话

页面以中文 InfoBar 说明精确主机、加密与清理语义。工具栏提供搜索；表格展示站点、保存时间、最近使用、计划清理和行级清除。临近到期状态使用警告徽标并附中文文字。批量清理放置在页面顶部，危险操作必须经过中文确认对话框。

### 5.6 设置/AI

设置页使用左侧内部分类导航和顶部搜索。当前具备实际行为的分类包括“翻译与 AI”和“存储与诊断”；本次不凭空增加无业务支撑的设置行为。

“翻译与 AI”分组包括：外部 AI 总开关、服务商、Base URL、模型、API Key 状态、替换、删除、连接测试、月度调用、Token 用量、预计费用、默认任务预算和用量明细。API Key 永不显示明文，只显示“已配置/未配置”和末四位提示。技术字段保留英文，其余标签、说明、状态和按钮为中文。

### 5.7 存储与诊断

页面包含容量单条分段使用条、页面快照/翻译缓存/日志分类、保留策略、分组清理和诊断包导出。清理分为普通临时数据、可重新生成缓存和不可恢复内部数据；最后一类必须使用危险样式和中文确认弹窗。诊断说明明确不包含 Cookie、Token、会话凭据或网页正文。

### 5.8 新建采集

对话框首先选择“直接粘贴 URL”或“导入 XLSX”，然后只显示对应字段。直接粘贴模式使用带行号的多行编辑区，支持 20 条或更多 URL；完成后显示有效、重复、无效数量和批次摘要。确认区说明学校数量、输出目录、访问合规提示和关键运行选项；主按钮显示“开始批次（N 所学校）”。

fixture 截图覆盖空输入、单 URL 和 20 URL 批量状态。输入校验、重复 URL 忽略、无效行阻止启动和业务任务创建继续使用现有逻辑。

## 6. 中文文案规则

### 6.1 必须中文化

应用名称、导航组名、页面标题、按钮、状态、空状态标题和说明、InfoBar、Toast、确认弹窗标题与操作、设置分类、搜索占位符、表格列标题、错误摘要和键盘提示全部使用简体中文。

### 6.2 可保留英文

仅保留必要技术名称或用户输入内容：API、API Key、URL、Base URL、Token、Excel、XLSX、DeepSeek、Windows DPAPI、robots、CAPTCHA、域名、模型 ID、任务 ID、运行 ID 和用户粘贴的 URL。

### 6.3 状态词表

统一使用：空闲、运行中、排队中、已完成、等待人工验证、建议复核、失败、已停止、已配置、未配置、测试成功、临近到期。

## 7. 响应式与可访问性

- `>=1360px`：220px 导航、主内容和 360px 检查器同时显示。
- `1180–1359px`：导航保持 220px，检查器可由用户关闭；表格隐藏低优先级列。
- `<1180px`：导航折叠为 56px，检查器以覆盖式抽屉出现；正文和控件字号不缩小。
- Tab 顺序从左到右、从上到下；表格支持方向键移动；Esc 依次关闭菜单、抽屉和对话框。
- Ctrl+F 聚焦当前页面搜索，Ctrl+, 打开设置，Ctrl+N 打开新建采集。
- 正文对比度至少 4.5:1；焦点环至少 2px；所有状态同时提供图标或文本。

## 8. 验收计划

### 8.1 截图状态

使用真实启动的 PySide6 窗口，在 1440×900 下采集以下 9 个状态：

1. 概览
2. 任务 + 右侧检查器
3. 人工验证
4. 运行历史
5. 站点会话
6. 设置/AI
7. 存储与诊断
8. 新建采集：单 URL
9. 新建采集：20 URL 批量

另在 1180×720 下验证导航折叠、检查器收起、内容滚动和弹窗不裁切。

### 8.2 交互烟雾验收

只验证不会触发真实副作用的 UI 行为：导航切页、设置分类切换、新建采集模式切换、空状态主操作、InfoBar/Toast 展示、确认弹窗打开与取消、键盘焦点和窗口缩放。真实抓取、AI 连接、浏览器验证、数据清理和导出属于后续功能回归，不作为本设计阶段的视觉通过条件。

### 8.3 通过条件

- 9 张真实运行截图与批准 mockup 的信息层级、中文文案、尺寸、密度和主次操作一致。
- 除允许的技术白名单和用户输入外，不出现英文用户界面文本。
- 1440×900 不裁切；1180×720 不破坏标题栏、一级导航、页面工具栏和主要操作。
- 空状态、状态徽标、InfoBar、危险确认和键盘焦点均符合设计令牌。
- `git diff` 只包含 UI、UI 验收 fixture、测试和设计相关文件；不包含业务逻辑或发布变更。

## 9. 交付顺序

1. 实现共享令牌、外壳和通用组件。
2. 先重做概览、任务和人工验证，建立列表/检查器/状态视觉基线。
3. 重做运行历史、站点会话和设置/AI、存储与诊断。
4. 重做新建采集对话框及 20 URL 批量状态。
5. 接入仅用于验收的内存 fixture，采集 1440×900 与 1180×720 截图。
6. 运行 UI 可访问性、中文白名单和交互烟雾测试，逐页与 mockup 对照。
7. 通过视觉验收后，才讨论是否进入 2.2.0 发布准备。

本设计不授权实现代码、发布变更或业务逻辑修改；这些动作必须在本设计文档获用户审阅后另行进入实施计划。
