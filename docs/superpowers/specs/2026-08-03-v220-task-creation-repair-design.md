# v2.2.0 任务创建修复设计

## 目标

让用户在 v2.2.0 的“新建采集”窗口粘贴有效教师目录 URL 后，可靠地创建 SQLite 任务并开始采集；若创建失败，提供可操作的提示和可诊断的脱敏原因。

## 范围

- 保持 v2.2.0 的 PySide6 界面、采集流程和 AI 策略不变。
- 将“创建任务”和“运行任务”拆成两个有边界的后台步骤。创建成功后立刻刷新任务列表；运行失败不会掩盖已创建的任务。
- 为创建前或首次写入 SQLite 时的失败新增脱敏诊断记录，使问题报告不再为空。
- 检测旧版 `tasks/*.json` 运行文件，并在界面中说明它们是旧格式、不会被自动执行；提供安全的只读可见性，而不自动重跑或复制任务。
- 打包仅以 PySide6 为默认桌面入口。保留 Tk 诊断入口只作为显式环境变量的维护通道；安装验证检查默认入口不会落到旧 UI。

## 数据流

1. URL 输入继续在对话框内标准化、去重并验证 `http`/`https`。
2. “开始批次”先提交 `create_direct_tasks`。成功后立即刷新任务页，并将返回的任务 ID 传给第二个后台命令。
3. 第二个命令执行 `run_task`。即使运行阶段失败，已持久化任务仍保留，可在任务页和诊断中查看。
4. 任一后台命令失败时，worker 生成不含 URL 查询参数、文件正文、Cookie、令牌或 API Key 的诊断事件。UI 显示稳定中文摘要和诊断文件位置。

## 错误与兼容性

- SQLite 锁、路径解析、权限和数据校验错误必须记录异常类别与脱敏消息。
- 不将旧 JSON 直接转换为新任务，避免在用户不确认的情况下重复采集。
- 旧 JSON 不影响新 SQLite 任务创建；界面明确说明其状态和恢复限制。

## 验收

- 有效单条 URL 会创建一条 SQLite `tasks` 记录，状态为 `ready`，并进入运行步骤。
- 人为注入创建失败时，任务列表不产生伪任务，UI 返回中文失败提示，导出的诊断 ZIP 含脱敏创建失败事件。
- 人为注入运行失败时，已创建任务继续存在，并且其错误可在任务/诊断中看到。
- 存在旧 JSON 运行文件时，界面显示兼容提示但不会自动执行或写入重复 SQLite 任务。
- 默认桌面入口解析为 PySide6 shell；仅设置 `FACULTY_CRAWLER_LEGACY_UI=1` 才解析旧维护 UI。
